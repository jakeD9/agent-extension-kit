# S23 — Focused v1 Hardening

Depends on S20. Harden the core v1 path without waiting for optional scheduled automation, parallel
review, additional Genkit providers, or the Claude harness. Complete focused injection,
authorization escalation, redaction, credential separation, publication reconciliation,
cancellation, lease, stale-worker, and resource-limit suites. Verify all three image targets,
Compose, health/readiness, non-root execution, termination, cleanup, trace redaction, and one
assembled fixture path across context, Genkit, Slack, Codex job, publication, and projection. Finish
recovery, rotation, compatibility, configuration, and verified-versus-mocked documentation. Exclude
production orchestrator manifests, automatic merge/deploy, unrestricted shell, and recursive
spawning.

Also prove the domain-authority dogma end to end: admitted developers receive the complete domain
corpus; non-admitted identities receive none; Git wins conflicts with supplemental memory; Mongo
knowledge can be rebuilt from an exact Git SHA; staging and active revisions never mix; and
transport or runner choice cannot promote content. Validate the projection storage boundary with
deterministic staging, failure, stale-job, rollback, and reconciliation fixtures. The kit does not
claim a provider publisher endpoint or workflow; platform mapping and organization-owned publisher
choices remain the S24 adoption documentation. Optional S17–S19, S21, and S22 capabilities carry
their own verification and are not v1 exit criteria.
